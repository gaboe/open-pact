# open-pact 0.9.0

## Breaking change: Windows SYSTEM jobs

Version 0.9.0 changes the Windows SYSTEM job. The job now runs the machine client that the package installs in the 64-bit Program Files folder. By default this is `C:\Program Files\open-pact-client\open-pact-client.exe`. The client does not copy that file anywhere. There is no migration from the SYSTEM job of an earlier version. Follow these steps in this order on each Windows device that runs a SYSTEM job.

Run every command in an elevated Windows PowerShell 5.1 prompt (`powershell.exe`, not `pwsh`).

### Step 1: Find the old SYSTEM task

Version 0.8.5 and earlier register the SYSTEM task with the principal SYSTEM. The task runs the old copy at `open-pact\open-pact-client.exe` in the 64-bit Program Files folder. A task of a limited user has the same name prefix, but it runs as that user. Do not remove a limited user task. The command below lists only tasks that run as SYSTEM and that run the old copy:

```powershell
& {
  $legacy = Join-Path $env:ProgramW6432 'open-pact\open-pact-client.exe'
  $system = @('SYSTEM', 'NT AUTHORITY\SYSTEM', 'S-1-5-18')
  $programs = @($legacy)
  Get-ScheduledTask -TaskPath '\' | Where-Object {
    $_.TaskName -like 'org.open-pact.report.*' -and
    ($system -contains $_.Principal.UserId) -and
    @($_.Actions | Where-Object { $_.Execute -and ($programs -contains ($_.Execute.Trim('"') -replace '^\\\\\?\\', '')) }).Count -gt 0
  } | ForEach-Object {
    'Task: ' + $_.TaskName
    'Actions: ' + @($_.Actions).Count
    'Program: ' + (($_.Actions | ForEach-Object { $_.Execute }) -join ' ')
    'Arguments: ' + (($_.Actions | ForEach-Object { $_.Arguments }) -join ' ')
  }
}
```

For each task, check two lines. The Actions line must show 1. The Program line must show the old copy. The program can start with `\\?\`. It is the same file.

If a task shows more than one action, version 0.8.5 did not create it. Open it in Task Scheduler and read every action. Remove it there only when you know each action. Do not use the block in step 4 for it.

For each task, write down the task name. Also write down the `--home` value and the `--user-home` value from its arguments. Copy each value without the quotes that Windows puts around it. Steps 3, 4 and 5 need these values. A value can contain an apostrophe. The commands take each value as data, so you do not escape it.

If you skip this step, the new client reports the old task as not its own. It then prints removal commands that suit the device.

### Step 2: Install the 0.9.0 package

Update the desktop app to 0.9.0 before you install the package. An older desktop app offers to remove the copy at `C:\Program Files\open-pact-client\open-pact-client.exe`.

Run this block. It installs exactly version 0.9.0. It upgrades an older package. It does not change a newer package.
```powershell
& {
if ($PSVersionTable.PSEdition -eq 'Core') { throw 'Run this block in Windows PowerShell 5.1: start powershell.exe as administrator, not pwsh.' }
$ErrorActionPreference = 'Stop'
$ProgressPreference = 'SilentlyContinue'
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$ErrorActionPreference = 'Stop'
function AssertProtected($path) {
    $item = Get-Item -LiteralPath $path -Force
    if ($item.Attributes -band [IO.FileAttributes]::ReparsePoint) { throw 'Protected path is a reparse point' }
    $acl = if ($item.PSIsContainer) { [IO.Directory]::GetAccessControl($path) } else { [IO.File]::GetAccessControl($path) }
    $allowed = @('S-1-5-18','S-1-5-32-544','S-1-5-80-956008885-3418522649-1831038044-1853292631-2271478464')
    $owner = $acl.GetOwner([Security.Principal.SecurityIdentifier]).Value
    if ($allowed -notcontains $owner) { throw 'Protected path has a non-admin owner' }
    foreach ($rule in $acl.GetAccessRules($true,$true,[Security.Principal.SecurityIdentifier])) {
        if ($rule.AccessControlType -eq 'Allow' -and -not ($rule.PropagationFlags -band [Security.AccessControl.PropagationFlags]::InheritOnly) -and ($rule.FileSystemRights -band 0xD0156) -and $allowed -notcontains $rule.IdentityReference.Value) {
            throw 'Protected path ACL grants write or modify to a non-admin principal'
        }
    }
}
$identity = [Security.Principal.WindowsIdentity]::GetCurrent()
if (-not (New-Object Security.Principal.WindowsPrincipal($identity)).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)) { throw 'Run this block from an elevated Windows PowerShell 5.1 prompt (powershell.exe).' }
$base = 'https://github.com/gaboe/open-pact/releases/download/v0.9.0'
$msiName = 'open-pact-client-x86_64-pc-windows-msvc.msi'
$folder = Join-Path ([Environment]::GetFolderPath('CommonApplicationData')) ('open-pact-install-' + [guid]::NewGuid())
if (Test-Path -LiteralPath $folder) { throw 'The install folder exists. Run this block again.' }
$security = New-Object Security.AccessControl.DirectorySecurity
$security.SetAccessRuleProtection($true, $false)
$security.SetOwner((New-Object Security.Principal.SecurityIdentifier('S-1-5-32-544')))
foreach ($sid in @('S-1-5-18', 'S-1-5-32-544')) {
    $account = New-Object Security.Principal.SecurityIdentifier($sid)
    $security.AddAccessRule((New-Object Security.AccessControl.FileSystemAccessRule($account, 'FullControl', 'ContainerInherit,ObjectInherit', 'None', 'Allow')))
}
[void][IO.Directory]::CreateDirectory($folder, $security)
AssertProtected $folder
foreach ($name in @($msiName, 'SHA256SUMS', 'SHA256SUMS.sigstore.json')) {
    Invoke-WebRequest -UseBasicParsing -Uri "$base/$name" -OutFile (Join-Path $folder $name)
}
$cosign = Join-Path $folder 'cosign.exe'
Invoke-WebRequest -UseBasicParsing -Uri 'https://github.com/sigstore/cosign/releases/download/v3.0.6/cosign-windows-amd64.exe' -OutFile $cosign
if ((Get-FileHash -LiteralPath $cosign -Algorithm SHA256).Hash -ne '9b85a88ebff2d9dd30ff4984a6f61f2cedc232dd87d81fa7f2ff3c0ed96c241c') { throw 'cosign.exe does not match its pinned hash.' }
$sums = Join-Path $folder 'SHA256SUMS'
& $cosign verify-blob --bundle (Join-Path $folder 'SHA256SUMS.sigstore.json') --certificate-identity 'https://github.com/gaboe/open-pact/.github/workflows/client-release.yml@refs/tags/v0.9.0' --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' $sums
if ($LASTEXITCODE -ne 0) { throw 'Cosign could not verify SHA256SUMS.' }
$lines = @(Get-Content -LiteralPath $sums | Where-Object { $_ -match '\S' -and (($_ -split '\s+', 2)[1].TrimStart('*') -eq $msiName) })
if ($lines.Count -ne 1) { throw 'SHA256SUMS must list the package once.' }
$msi = Join-Path $folder $msiName
if ((Get-FileHash -LiteralPath $msi -Algorithm SHA256).Hash -ne ($lines[0] -split '\s+')[0]) { throw 'The package does not match SHA256SUMS.' }
$log = Join-Path $folder 'install.log'
$msiexec = Join-Path ([Environment]::SystemDirectory) 'msiexec.exe'
$install = Start-Process -FilePath $msiexec -ArgumentList ('/i "' + $msi + '" /qn /norestart /l*v "' + $log + '"') -Wait -PassThru
Write-Output ('msiexec exit code: ' + $install.ExitCode)
if ($install.ExitCode -eq 3010) { Write-Output 'Restart Windows to finish the install.' }
elseif ($install.ExitCode -ne 0) { throw ('The install failed. See ' + $log) }
}
```

To repair a package of the same version, run these commands in the same prompt. Write the full path of the verified MSI between `@'` and `'@`. The block leaves that MSI in its folder under `%ProgramData%`. The commands wait for `msiexec` and stop when it fails.

```powershell
$msi = @'
<the full path of the verified MSI>
'@
$msiexec = Join-Path ([Environment]::SystemDirectory) 'msiexec.exe'
$repair = Start-Process -FilePath $msiexec -ArgumentList ('/fa "' + $msi + '" /qn /norestart') -Wait -PassThru
if ($repair.ExitCode -eq 3010) { Write-Output 'Restart Windows to finish the repair.' }
elseif ($repair.ExitCode -ne 0) { throw ('The repair failed. Exit code: ' + $repair.ExitCode) }
```

Repair only from a folder that only administrators can change, such as the folder of the install block. Windows Installer repairs from the folder of the last install. When a standard user can write to that folder, the user can put another MSI with the same package code there, and an elevated repair then installs the files of that MSI. Do not install or repair the package from a share or a folder that standard users can change.

If the block asks for a restart, restart Windows and then do step 3.

### Step 3: Check the profile of the task

Version 0.9.0 accepts only some profile folders. A dry run applies the same rule as the real command, and it changes nothing. Run it once for each task from step 1. The dry run checks the profile folder, not the device key. Do not remove the old task before it succeeds.

1. Replace the line `<the absolute client home>` with the `--home` value from step 1.
2. Replace the line `<the profile folder of the user>` with the `--user-home` value from step 1.
3. Keep each value on its own line, between `@'` and `'@`. Do not add quotes.

```powershell
$q = Join-Path $env:ProgramW6432 'open-pact-client\open-pact-client.exe'
$clientHome = @'
<the absolute client home>
'@
$userHome = @'
<the profile folder of the user>
'@
if (-not (Test-Path -LiteralPath $q -PathType Leaf)) { throw 'The machine client is missing. Install the package, then run this command again.' }
$global:LASTEXITCODE = $null
& $q --home $clientHome schedule on --system --user-home $userHome --dry-run
if ($LASTEXITCODE -ne 0) { throw 'The dry run failed. Do not remove the old task. Fix the error, then run this command again.' }
```

The command prints `The job scans <profile>.` It then says that the old SYSTEM task blocks the install. This message is normal, because step 4 removes the old task. An error is not normal. When the command fails, do not do step 4. Read the error. If the error names the profile folder, pick the profile folder of the user whose repositories the job reads, for example `C:\Users\example`. Run the dry run again with that value. Then use that value in step 5. Do not start step 4 until a dry run passes. For any other error, fix what it names and run the dry run again.

On a TPM-backed home, the administrator who joined the device must run steps 3 to 5. Only that account and SYSTEM can open the TPM key. The dry run checks the profile folder, not the key. If another administrator runs the upgrade, step 4 removes the old task, and then the new job cannot open the key.

### Step 4: Remove the old SYSTEM task

Run the next block once for each task from step 1, after its dry run succeeded. Do not run it for a task of a limited user. The block deletes the task name that you give it and does not check the program. Replace two samples in the block:

1. Replace the task name `org.open-pact.report.0123456789abcdef` in every place where it appears.
2. Replace the home line `C:\Users\example\pact`, between `@'` and `'@`, with the `--home` value from step 1. Do not add quotes.

```powershell
& {
  $schtasks = Join-Path ([Environment]::SystemDirectory) 'schtasks.exe'
  function Test-TaskRegistered {
    # The Task Scheduler COM API reports a missing task as HRESULT 0x80070002, in every display language.
    $service = New-Object -ComObject Schedule.Service
    $service.Connect()
    try {
      [void]$service.GetFolder('\').GetTask('\org.open-pact.report.0123456789abcdef')
      return $true
    } catch {
      $e = $_.Exception
      while ($e.InnerException) { $e = $e.InnerException }
      if ($e.HResult -eq -2147024894) { return $false }
      throw ('Could not query the task. ' + $_)
    }
  }
  function End-TaskQuietly {
    # /End fails for a task that is not running. That does not matter here: /Delete decides.
    $ErrorActionPreference = 'Continue'
    & $schtasks /End /TN 'org.open-pact.report.0123456789abcdef' 2>$null | Out-Null
  }
  if (Test-TaskRegistered) {
    End-TaskQuietly
    & $schtasks /Delete /TN 'org.open-pact.report.0123456789abcdef' /F
    if ($LASTEXITCODE -ne 0) { throw 'The task was not removed. Run this block again from an elevated prompt.' }
  }
  if (Test-TaskRegistered) { throw 'The task is still registered. Run this block again.' }
  $q = Join-Path $env:ProgramW6432 'open-pact-client\open-pact-client.exe'
  if (-not (Test-Path -LiteralPath $q -PathType Leaf)) { throw 'The machine client is missing. Install the package, then run this block again.' }
  $clientHome = @'
C:\Users\example\pact
'@
  $global:LASTEXITCODE = $null
  & $q --home $clientHome schedule off
  if ($LASTEXITCODE -ne 0) { throw 'schedule off failed. Do not uninstall the package. Fix the error, then run this block again.' }
}
```

The block deletes the task. It then checks that the machine client exists and runs `schedule off` with it. `schedule off` removes the job state and the applied-settings receipt. It saves automatic sending as off. The block throws when the file is missing or when `schedule off` fails. Do not start the new job then. Fix the error and run the block again.

The old copy in the `open-pact` folder of Program Files stays. Remove that folder after you remove every open-pact SYSTEM task of this device.

### Step 5: Start the SYSTEM job

Run these commands once for each task that you removed. Use the same two values as in step 3. The commands resolve the client by its full path, so an older client on PATH never runs. They stop when the client file is missing or when the command fails.

1. Replace the line `<the absolute client home>` with the `--home` value from step 1.
2. Replace the line `<the profile folder of the user>` with the `--user-home` value that passed step 3.
3. Keep each value on its own line, between `@'` and `'@`. Do not add quotes.

```powershell
$q = Join-Path $env:ProgramW6432 'open-pact-client\open-pact-client.exe'
$clientHome = @'
<the absolute client home>
'@
$userHome = @'
<the profile folder of the user>
'@
if (-not (Test-Path -LiteralPath $q -PathType Leaf)) { throw 'The machine client is missing. Install the package, then run this command again.' }
$global:LASTEXITCODE = $null
& $q --home $clientHome schedule on --system --user-home $userHome
if ($LASTEXITCODE -ne 0) { throw 'schedule on failed. Fix the error, then run this command again.' }
```

The command registers the new task and writes new job state. It records that automatic sending is on.
